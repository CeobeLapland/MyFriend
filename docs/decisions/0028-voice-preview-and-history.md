# ADR 0028 — 语音预览模式、会话列表与记忆抽取的门槛

> 阶段 3 交付后用户实机试用提的三件事：① 本地 STT 错字多，转写结果该先让人改；
> ② 对话历史"形同虚设"（只有当前一段，翻不回旧的）；③ 记忆记得太杂。
> 本文记录这三处的做法，其中 ① 是**协议扩展**（新增一帧，不动既有帧）。

## Decision

### 1. 语音预览：新增 `session.stt_preview.set`（默认关），Studio 默认开

- 打开后，``input.audio.*`` **只走 STT**：服务端发完 ``stt.final`` 就停下，
  **不起 turn**；由客户端把转写填进输入框，用户改完再用 ``input.user_text`` 发。
- **默认关**：``/dev`` 与 Unity 的既有行为（说完直接答）不变——只有显式打开这条的客户端受影响。
- Studio 侧是一个勾选框「识别后先填进输入框」，**默认勾上**（本地 STT 错字多的现实），
  偏好存在 localStorage，重连时补发。
- **已知代价**：预览模式下这一轮的 ``emotion_hint`` 用不上（后面走纯文本路径，没有 hint）。
  服务端会记一条 ``stt.preview`` 日志写清 ``hint_dropped``，不假装它还在。

### 2. 会话列表：`GET /v1/conversations`（列表端点），Studio 左侧常驻历史栏

- 之前只有"建会话"与"读某段的消息"，**没有列表**——所以 UI 只能记住当前那一段
  （`localStorage` 里的一个 id）。这是后端缺能力，不只是 UI 缺入口。
- 新端点返回：会话 id / 状态 / 开始与结束时间 / 消息数 / 最后一条消息的角色与**截断摘要**
  （80 字，`…` 结尾）。完整历史仍走 `/{id}/messages`。
- **排序按消息 id 倒序**（ULID，ADR 0012），不按时间戳——本机时钟分辨率分不出同一毫秒。
- 后端仓储新增 `list_summaries`：两条查询（会话+计数+最后消息 id；再一次性取那批消息），
  不做 N+1。
- 客户端发消息时**带上 `conversation_id`**：不带的话服务端只会写进"最近一段 active 会话"，
  用户在历史栏点开旧会话再说话就会跑到别处去。
- 已结束的会话**只读**（ADR 0012 的既有语义）：UI 打开时就提示"只读，接着聊请开新会话"，
  不静默改写别的会话。

### 3. 记忆：提高抽取门槛 + 给出可调旋钮（不做"每轮必记"）

- 现状：LLM 每轮返回 `memory_candidates`，最多 3 条落库（`memory_max_candidates_per_turn`），
  没有重要性下限。实测体验是"垃圾记忆一堆"。
- **提示词层**（`domain/prompt.py` Layer 8）把门槛写死：只放用户**明确说出口的长期事实**；
  寒暄、一次性安排、玩笑、推测一律不放；**拿不准就留空**，且明说"不要为了收集记忆而提问"
  ——后一句同时也是"咨询师腔"的一个来源（模型为了填字段去挖话题）。
- **配置层**：把 `ASTRA_MEMORY_MAX_CANDIDATES_PER_TURN`（0 = 不自动记）与
  `ASTRA_MEMORY_TOP_K`（注入条数）加进 Studio 设置页的可编辑白名单；
  彻底不要记忆仍可用 `ASTRA_MEMORY_ENABLED=false`（不写不检索）。已有的历史记忆
  在记忆页可逐条删或清空。

## Reason

- **为什么预览是"协议开关"而不是"前端自己拆"**：转写是在服务端做的，而起不起 turn
  也在服务端决定；前端拿到 `stt.final` 时那一轮已经跑起来了，拦不住。
- **为什么默认关**：`/dev` 是协议调试工具，行为要保持"说完就答"；Unity 端有它自己的交互，
  不该被 Studio 的偏好改变。
- **为什么摘要放列表里而不是让前端自己拉**：N 段会话就要 N 次
  `/{id}/messages`（每段都是全量历史）；服务端一次查询就能给出"够认出来"的那一行。
- **为什么记忆不做成"每轮必记"**：记忆的价值在**筛选**。宁可少记、但要记得准，
  否则检索质量、上下文预算、人格一致性都会被稀释。

## Consequences

- 协议新增一帧（`session.stt_preview.set`），**既有帧一行未改**；`docs/04` 的帧表要补这一行。
- Studio 的对话页多了一列常驻历史栏（216px）；窄窗口下主区会变窄，属已知取舍。
- 记忆仍会写入，只是门槛更高；用户若要"完全不记"需显式关掉或把每轮条数设 0。
- 人格"咨询师腔"的另外两条防线在配置里（`personas/astra.toml` 的 `behavior.rules` 与
  `prompt.hard_constraints`），用户可自行增删——协议层的反模板约束不可配置。
- 已被"格式化"的历史会继续影响模型：修完提示词后建议**开一段新会话**（现在有历史栏，
  随时能翻回旧的）。
